💡 MVVM rules to remember:
  • → Model = plain data (struct), no UI, no logic. import Foundation only.
  • → ViewModel = the brain. ObservableObject, @Published, functions, computed properties. import Foundation only.
  • → View = pure UI. SwiftUI struct + body. Reads from VM, calls VM functions. import SwiftUI.

App requirements

This is the only documentation you have. There is no starter code — you must figure out which chunks belong in which file based on MVVM rules.

◆ Sarah's spec

  • Each saved entry stores: a mood name, an emoji, an optional note, an intensity (1-10), and a timestamp
  • The Model is named MoodEntry and conforms to Identifiable
  • The ViewModel is named MoodViewModel and tracks: the current selection, the entered note, the intensity, and the saved history
  • The ViewModel has a computed property canSave — true only when a mood is selected
  • The ViewModel has a function selectMood(name:emoji:) that sets both selection fields
  • The ViewModel has a function saveMood() that creates a MoodEntry, inserts it at the top of history, then resets the form
  • The View is named MoodView and shows: an emoji row, a note text field, an intensity slider, a Save button, and a history list
  • The Save button is disabled when vm.canSave is false
  • Files: MoodEntry.swift (Model), MoodViewModel.swift (ViewModel), MoodView.swift (View)
💡 Reminder: Same MVVM rules as Part 1.
  • → Model = data only. import Foundation.
  • → ViewModel = state + logic. ObservableObject, @Published. import Foundation.
  • → View = UI. import SwiftUI, reads from VM, calls VM functions.
